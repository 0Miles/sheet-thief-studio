# 帳號用帳號密碼登入，只由管理者在後台建立

平台只給自己和認識的樂團用，所以不開放註冊，也不接 OAuth：管理者在後台建立帳號並設定初始密碼，使用者登入後可以自己改密碼。密碼以 argon2id 雜湊；登入狀態是伺服器端的 session，放在 HttpOnly cookie。

之後要加上「由 karyl-chan bot 私訊登入或註冊」。為了那時候不必搬資料，帳號和登入方式分開存：`accounts` 是人，`identities` 記錄這個人可以用哪些方式登入（現在只有密碼一種）。

考慮過、沒採用的做法：

- **OAuth（Google、Discord）。** 不必自己管密碼，但要註冊並維護 OAuth 應用程式，而且仍然需要一份「誰可以進來」的名單；對這個規模是多餘的。
- **沿用 Sheet Thief 的匿名瀏覽器身分。** 沒辦法邀請特定的人，清掉 cookie 就失去樂句庫。

## Consequences

- 沒有「忘記密碼」的自助流程：由管理者重設。
- 第一個管理者帳號用伺服器上的指令建立。
- 唯讀連結不需要帳號，所以權限檢查要同時處理「已登入的成員」和「持有連結的訪客」兩種來源。
